# DualDock Implementation Plan

> **For agentic workers:** Use native execution for integration, with independently owned modules delegated in parallel. Track verification below.

**Goal:** Deliver a personal macOS Dock with horizontal app groups, window previews, standard/running-only modes and one shared layout on every logical display.

**Architecture:** One persisted configuration supplies all screen panels. AppKit owns nonactivating panels and drag interaction; SwiftUI renders settings. ScreenCaptureKit supplies on-demand screenshots; Accessibility and optional dynamically resolved private APIs identify and activate windows.

**Tech Stack:** SwiftPM, Swift 5.9 language mode, macOS 14+, AppKit, SwiftUI, ScreenCaptureKit, ApplicationServices; no third-party dependencies.

**Spec:** ../specs/2026-11-09-dualdock-design.md. User approved scope on 2026-11-09 after all functional choices.

## Global Constraints

- Product name DualDock. Local .app for the user's own Mac.
- Shared layout and mode on every logical screen. Skip mirrored follower displays.
- Horizontal group popup. Running-only flattens regular running apps without mutating saved groups.
- Initially import native Dock pins; subsequent edits belong to DualDock. Reimport is explicit.
- System Dock hiding is opt-in; preserve settings, restore on normal exit and recover after interrupted sessions.
- Per-display fullscreen hides only that display's panel. Private APIs are optional and guarded.

## Review Focus

- Drag between groups, reorder and duplicate drops must preserve unique membership and the user's layout.
- Missing/corrupt config must remain recoverable. Running-mode round trips preserve saved data.
- Hover tasks that complete after pointer changes must never display stale previews.
- Screen detach and full-screen transitions must dismiss associated popups and leave other screens working.
- Restoring system Dock must not overwrite settings subsequently changed by the user.
