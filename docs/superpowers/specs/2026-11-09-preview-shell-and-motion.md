# DualDock 1.2.3：隐藏空壳预览与动画平顺性

## 要求

排除微信空白预览卡片，修正鼠标经过图标分界处的晃动，并检查展开应用夹后的横向触控板滚动卡顿。动画采用合理的内置默认速度，不增加滑块或配置字段。

## 已定位的问题

- 微信有一个不在成功返回的 AX 窗口列表中的隐藏预建窗口，截图内部为纯色，只带极少量窗口装饰；旧策略因它有标题和不透明像素而保留。
- 放大焦点被单个图标命中控制，鼠标进入分隔线空隙会清空焦点、缩回，随后重新放大。
- 每次鼠标移动改目标时都重置动画时钟，导致动画步进受到鼠标事件频率影响。

## 修正原则

空壳筛选结合屏内状态、可靠且非空的辅助功能窗口集合、运行时应用名称及图像内部信息，只排除明确的隐藏预建壳；不以纯色图像单独判定，不删除正常空白文档、文章、文件或最小化窗口。截图统计在内存中进行。

将连续放大区域与单个图标的点击、预览命中分开，分隔线仍属于连续放大区域。跟随鼠标和移出恢复分别使用非振荡平滑过渡，恢复节奏更缓；持续动画改目标时保留时钟，暂停、结束时清理。继续保持底板、窗口和滚动位置固定，以及减少动态效果设置的即时路径。

应用夹滚动实测发现逻辑内容已完整适配，但 AppKit 像素取整导致约 0.15 pt 的虚假滚动范围。视口向外对齐 backing pixels，适配内容与实际 clip 尺寸一致；无溢出时忽略滚动输入，不触发无效 hover 刷新。滚轮转发加入重入保护，避免边界事件沿 responder chain 回到同一滚动视图。保留真实溢出内容的手动滚动。离屏 CPU 测量未证明硬件帧率下降，将组件问题与触控板现场手感分开记录。
