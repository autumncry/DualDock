# DualDock 多屏尺寸、动画与预览改进

用户于 2026-11-09 明确要求继续修改六项内容，并确认右键菜单语义及两滑块方案。此文是本轮实施依据。

## 已确认交互

- 两屏共享 Dock 大小，修改设置应同时可见地生效。
- 两个连续滑块分别控制整条 Dock 大小与图标间距（紧凑到宽松）。屏幕适配限制可见区域宽度，超长内容横向滚动，基础图标尺寸不按屏分别截断。
- 鼠标附近的图标平滑放大，邻近图标渐变衰减，支持开关与连续放大幅度设置。
- 预览只显示本次成功捕获且包含可见像素的实际窗口，去掉重复 ID、已关闭窗口、无图或全透明卡片。同标题但不同 ID 且确有内容的窗口保留。只有一张预览时在窗格内居中。
- 右键菜单整体位于当前图标上方，水平居中并约束在当前屏幕可见范围。Control-click 同样处理，菜单结束不误启动应用。
- 应用组使用文件夹顶签、前后层面和内部小图标，与普通 App 的圆角方图标形成明确形状差异。横向展开方式维持用户已确认的行为。

## 已取得的依据

1. 用 v1.0.1 的实际 DockStripView 隔离复现：内屏可见宽度 1768 pt 时，设置 48/64/72 的实际图标均被截为约 35.06 pt；外屏 2976 pt 仍变化。根因是每屏 `min(iconSize, availablePerTile - 14)`。
2. Dockish 官方帮助提供 Icon Size、Spacing、Magnification 和峰值大小，强调超长 Dock 不自动缩图标。参考其大小/间距独立控制，DualDock 额外用可滚动视口处理溢出。来源 https://appish.app/dockish/help 。
3. REA `inspect-evidence-bundle` 复核 Dockish 的 `FolderIconStyle`、`stackPreview`、`folderGlyph`，Evidence 为 `ev_c3e4db82b47d5939b2162fe578ec5b47ef2a59307c66134861724391d45363da`。未恢复 folderGlyph 的精确颜色/绘制路径。
4. Docky 的开源 AppFolderTileView 提供四格与三层错位堆叠，FolderTileView 使用系统文件夹图标。仅参考视觉原则，本项目以原生矢量独立绘制。
5. Clash Verge 正常 AX 查询下当前已只有一张预览；模拟 AX 覆盖未知时，旧实现稳定多出全透明 helper。新要求从输出层严格排除没有有效截图的卡片，与 AX 查询是否可用解耦。
6. CC Switch 单张预览偏左源于宽度下限与固定起始 x 不一致，提取实际布局计算并以居中/等距不变量回归验证。

## 实现约束

- 现有 iconSize 作为整体大小基准，连续范围 24–96，100% 对应 48。边距、按钮与轮廓按同比例缩放。
- iconSpacing 连续范围 0–32，旧配置缺省 14 以保留原图标之间的有效空隙。
- magnificationScale 连续范围 1–2.5，缺省 5/3；每屏单独保存瞬时悬停状态，配置全局共享。
- 加入新字段时兼容读取 v1 配置、保留分组和排列，保存升级前备份；新 schema 为 2，未来未知版本继续只读保护。
- 集中管理鼠标追踪与动画，不让每帧布局重复触发 entered/exited 和预览取消。真实 frame 与点击命中一致，面板向上增长，底边保持固定。
- 拖拽、菜单期间冻结图标位置。显示器移除、全屏隐藏和退出时释放动画资源。
- 弹窗锚点在实际展示时从当前图标矩形读取，避免放大动画后使用旧坐标。
