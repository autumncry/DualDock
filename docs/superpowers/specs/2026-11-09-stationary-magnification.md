# 固定 Dock 位置的放大交互修正

用户在 v1.1.0 实机验收中指出，鼠标左右滑动会让整条 Dock 横移，并触发下方滑块。用户明确要求参考原生 Dock 的交互表现，另确认应用过多时可以保留手动横向滚动，但不显示滑块。右键菜单应向图标右上方偏移。

## 故障证据

真实 Core 布局回放在旧实现中得到 15 项违反。9 个图标、48 pt、2 倍放大时，基础宽度640，悬停宽度变为724–760；最大宽度700时又产生24–60的新增滚动范围。旧协调器根据 `mouseX - focusX` 移动窗口，视图随后按偏差修改 scroll offset。

Apple 官方文档将 Magnification 描述为指针下图标放大及独立放大尺寸设置，未公开内部曲线或布局算法。只读观测中，当前隐藏的原生 Dock 具有整屏绘制窗口；该单帧不足以恢复其事件区域机制。本项目依据用户明确的交互要求实现局部图标放大，不把普通 NSPanel 跟随鼠标平移视为原生行为。

参考 https://support.apple.com/guide/mac-help/change-desktop-dock-settings-mchlp1119/mac 。

## 本轮约束

- 在设置、应用列表和显示器布局不变时，悬停及鼠标横移不改变 panel 的 x、width、底边 y。
- 水平 panel、viewport、document 尺寸使用固定、可见的放大包络。预留空间有界，不建立整屏透明窗口拦截桌面。
- 指针映射基于固定基础布局，图标放大和邻居让位发生在栏内。实际 frame 与命中区域一致。
- 悬停绝不主动修改横向 scroll offset，也不产生新的滚动范围。
- 水平和垂直滚动条均隐藏，关闭弹性滚动。只有用户明确的滚轮/触控板操作改变可见内容。
- 已手动滚动时，局部图标几何可调整以保证当前放大的图标可见，窗口本身与 offset 不移动。远端图标可以处在原有视口之外。
- 右键菜单左侧从图标中心右侧8 pt处开始，向上展开；屏幕边界仍优先约束。

本约束取代此前根据鼠标锚点移动 panel 的实现选择。配置格式和已有分组不变。

## 验证

以原红回放转绿验证固定水平尺寸和无新增滚动范围。覆盖不同屏宽、所有焦点位置、密集溢出、手动滚动后的边缘图标、插值过程以及菜单右偏/屏幕边界。实际 AppKit 离屏检查应核对 NSClipView offset 和隐藏滚动条状态。
