# DualDock 1.2.2：图标联动与窗口预览身份

## 本次用户反馈

用户提供 DualDock 与原生 Dock 对比截图，要求去掉图标背后的悬停底色，并让附近图标产生连带放大。此次反馈替代 1.2.1 的“仅当前图标”行为，继续保留此前已确认的固定底板、无滚动条、菜单栏及空白右键设置入口。飞书实际只有一个窗口，却出现“飞书”和“Feishu”两张预览，需要修复。

## 实现方向

- 普通悬停只绘制应用图标、运行指示点和通知角标，保留拖拽合组时的明确反馈底色。
- 中心及两侧图标连续衰减放大，并在固定画布内让位，防止遮挡。固定底板、窗口、文档、视口尺寸及手动滚动位置不随 hover 改变。焦点计算与实际图标点击命中分离，避免布局变化反过来造成抖动。
- 两端图标和内容溢出时，焦点与可见范围约束保持连续，防止末端图标从鼠标下消失或在焦点跨过半格时突然横跳。
- 窗口预览以实际窗口身份和辅助功能元数据判定。只读实测发现飞书主窗口 AXStandardWindow 与同位置/尺寸的 WatermarkWidget 辅助窗口（AXUnknown），是不同窗口 ID；辅助窗口截图包含有效像素，SCK 标题为空后回退为 Feishu。仅靠有效像素和 ID 去重无法解决。
- 排除有明确证据的非交互辅助叠层，不按应用名称、窗口标题或截图相似度合并，不压掉正常多窗口。权限或窗口元数据不可用时保留明确回退。

## 验证

回归覆盖中心/邻居尺寸衰减、焦点连续性、无重叠、窗口和底板固定、手动 offset 保留、移入移出命中以及悬停底色消失。窗口回归覆盖真实主窗与辅助叠层、多标准窗口同标题、最小化/其他空间窗口以及未知元数据。用实际飞书只读探针确认过滤结果；不把消息内容或窗口截图上传仓库。
